## A note on data

This environment has no Kaggle access, so `data/raw/` currently holds a **synthetic,
schema-accurate stand-in** for the KKBOX tables, generated by
`src/data/make_synthetic.py`. Every downstream module (features, training, API) depends
only on the column contract in the spec (§2.1), so swapping in the real competition data
via `src/data/ingest.py` requires no code changes — just re-run the pipeline.

To use the real data:
```bash
export KAGGLE_USERNAME=... KAGGLE_KEY=...   # or ~/.kaggle/kaggle.json
python -m src.data.ingest
```

To regenerate the synthetic stand-in instead:
```bash
python -m src.data.make_synthetic --n-members 2000 --seed 42
```

## Running the Week 1–2 pipeline

```bash
# 1. Get data (synthetic, or real via ingest.py above)
python -m src.data.make_synthetic --n-members 2000 --seed 42

# 2. Sanity-check features (no leakage, no unexplained nulls)
python -m src.data.features

# 3. Train, track in MLflow, register to Staging
export MLFLOW_TRACKING_URI="sqlite:///mlflow.db"
python -m src.models.train

# 4. Serve
export MODEL_STAGE=Staging
uvicorn src.api.main:app --port 8000

# 5. Try it
curl localhost:8000/health
curl -X POST localhost:8000/predict -H "Content-Type: application/json" -d '{
  "msno": "string", "recency_days": 4, "txns_last_90d": 3,
  "active_days_last_30d": 18, "engagement_trend": -0.12, "plan_price": 149,
  "is_auto_renew": true, "age": 27, "tenure_days": 812
}'
```

MLflow UI: `mlflow ui --backend-store-uri sqlite:///mlflow.db`

## Week 2 — Model & Tracking

| Task | Status |
|---|---|
| W2-T1 Feature engineering pipeline | `src/data/features.py` — one row per member, leakage-guarded against each member's own `anchor_date` (their latest `membership_expire_date`, per §2.2), zero unexplained nulls |
| W2-T2 Model training | `src/models/train.py` — logistic regression baseline + XGBoost candidate, time-based split |
| W2-T3 MLflow tracking | experiment `churncast-training`, tags `model_type` / `feature_version`, full params+metrics+artifact logging |
| W2-T4 Model registry | registers `churncast-model`, promotes best run to `Staging` |
| W2-T5 FastAPI service | `src/api/main.py` — `/predict`, `/health` per §6, loads from `MODEL_STAGE` at boot |

**Known gap:** on the current synthetic dataset the best model reaches AUC-ROC ≈ 0.59,
below the ≥0.70 target in §4 W2-T2. The synthetic generator's churn signal is
intentionally thin (correlated only with auto-renew/cancel flags) so the pipeline could
be validated without the real ~1M-row KKBOX tables. This should close substantially once
real data replaces the synthetic set — flagging per §8.4 rather than blocking on it.
